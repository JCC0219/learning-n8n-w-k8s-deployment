# My Personal Portfolio

## Side Project Overview

**Project Name:** My Personal Portfolio
**Website:** https://www.jcchiew.com/
**Repository:** https://github.com/JCC0219/jc-portfolio-nextjs
**Started:** January 2025
**Status:** Present / Ongoing
**Project Type:** Personal Portfolio, Full-Stack Application, Cloud Infrastructure, DevOps, AI Assistant, RAG Knowledge Base, and Automation Project

My Personal Portfolio is JC's personal professional website built to showcase his professional profile, work experience, technical skills, projects, and engineering journey.

The project has evolved beyond a traditional portfolio website. It has become a personal engineering laboratory where JC experiments with and applies technologies across full-stack development, cloud infrastructure, DevOps, networking, domain management, CI/CD, Kubernetes, workflow automation, AI agents, RAG, and large language models.

The portfolio also includes a personal **JC AI Assistant**, allowing visitors to interact with an AI-powered chatbot and learn more about JC's background, professional experience, skills, and projects through conversational interaction.

The project is particularly significant because it represents JC's hands-on learning journey. Instead of only building the frontend of a personal website, JC progressively expanded the project into a more complete system involving application development, infrastructure management, network and domain management, automation, AI integration, and knowledge retrieval.

# AI Assistant Architecture

The JC AI Assistant is designed as an AI-powered conversational interface connected to JC's portfolio knowledge.

The high-level flow is:

**User**

→ **Portfolio Website**

→ **AI Assistant**

→ **AI / LLM Workflow**

→ **RAG Knowledge Retrieval**

→ **Relevant Portfolio Knowledge**

→ **LLM Response**

→ **User**

The assistant is designed to answer questions based on JC's portfolio knowledge rather than relying only on the model's general knowledge.

The goal is to ensure that responses about JC's professional background, experience, skills, and projects are grounded in the portfolio knowledge base.

The AI assistant follows the principle that the portfolio knowledge base is the source of truth for information about JC.

The assistant should not invent professional experience, projects, technologies, certifications, or other personal information that is not supported by the available knowledge.

---

# RAG Knowledge Base

The portfolio uses a RAG-based knowledge architecture to provide the JC AI Assistant with structured information about JC.

The knowledge base contains information covering areas such as:

* Professional background.
* Work experience.
* Technical skills.
* Cloud experience.
* Certifications.
* Personal projects.
* Project architecture.
* Project technology stacks.
* Project evolution.
* Learning experiences.
* Personal interests where relevant.

The purpose of the RAG system is to allow the AI assistant to retrieve relevant information based on the user's question.

For example:

If a visitor asks:

> "What did JC learn from building his portfolio?"

The system should retrieve information related to the portfolio's evolution and learning outcomes.

If a visitor asks:

> "How does JC's portfolio use Kubernetes?"

The system should retrieve the infrastructure-related knowledge.

If a visitor asks:

> "What AI technologies did JC use?"

The system should retrieve the AI assistant, RAG, n8n, LLM, and AI provider information.

The knowledge base is therefore structured so that different aspects of the project can be retrieved independently instead of storing all project information as one unstructured block.
